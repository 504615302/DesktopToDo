# 模型服务商目录与在线更新设计

## 背景与目标

当前应用已经支持 OpenAI Chat Completions 兼容接口，但新增模型配置仍依赖用户手动填写访问地址和模型名称。本次改造将常见服务商变成可选择的内置目录，在选择服务商或模型时自动补全兼容地址，同时保留完全自定义能力。

目标：

- 内置常见 OpenAI 兼容服务商及推荐模型。
- 服务商、访问地址、模型名称三者联动，用户通常只需输入 API Key。
- 模型名称既可下拉选择，也可直接手动输入。
- 提供“更新模型”按钮，使用当前服务商、地址和密钥同步其最新模型列表。
- 在线同步失败不影响已有配置与内置列表。
- 继续使用系统现有的凭据加密机制保存 API Key。

非目标：

- 不接入 Claude 原生 Messages API 等非 OpenAI 协议。
- 不实现各服务商的专有高级能力。
- 不自动注册、购买或申请任何服务商密钥。

## 用户体验

“新增模型”对话框按以下顺序展示：

1. 配置名称。
2. 服务商：可选择内置服务商，也可选择“自定义”。
3. 访问地址：选择内置服务商后自动填写，仍允许编辑。
4. 模型：可编辑下拉框，展示内置清单、在线同步结果和当前手动值。
5. API Key。
6. 高级参数：温度、最大输出长度等现有字段。

模型框右侧放置“更新模型”按钮。按钮点击后立即进入忙碌状态并禁用重复提交，但不锁死整个对话框。成功时更新下拉列表并显示新增数量；失败时保留原列表，在字段附近显示可恢复的错误信息。

选择服务商时：

- 自动填入该服务商的默认 OpenAI 兼容地址。
- 切换到该服务商的内置与本地缓存模型清单。
- 如果用户此前手动修改过地址，切换服务商才会替换地址；普通编辑模型不会改写地址。

选择模型时不额外改变服务商和地址，以避免模型名称重叠带来的误判。用户选择服务商后再选择模型，是唯一的自动联动方向。

## 内置目录

首批目录覆盖：OpenAI、Google Gemini、DeepSeek、通义千问、Kimi、智谱 GLM、OpenRouter、SiliconFlow，并保留“自定义”。

每个目录项包含：

- 稳定的服务商标识。
- 显示名称。
- 默认 OpenAI 兼容 Base URL。
- 少量推荐模型，用于离线首次使用。
- 是否预期支持 `GET /models`。
- API Key 是否必填。

内置模型清单只作为启动默认值，不宣称永久最新。易变化的完整列表由“更新模型”获取。实现时应把目录集中在单一模块中，避免 UI、服务层和测试各自维护一份。

所有 Base URL 在保存及请求前统一移除尾部斜杠，再拼接 `/models` 或 `/chat/completions`，防止双斜杠。Google Gemini 的默认地址使用 `https://generativelanguage.googleapis.com/v1beta/openai/`，规范化后存储。

## 在线模型同步

同步流程：

1. 校验服务商、Base URL 和需要的 API Key。
2. 请求 `{normalized_base_url}/models`，沿用 Bearer Token 认证方式。
3. 解析 OpenAI 风格响应的 `data[].id`。
4. 去除空值和重复项，按不区分大小写的自然顺序排序。
5. 将在线结果与内置列表、当前输入值合并。
6. 将成功结果按“服务商 + Base URL”写入本地缓存，并记录更新时间。

缓存不保存密钥。再次打开对话框时优先显示“内置 + 缓存”结果，因此离线时仍可使用最近一次成功同步的数据。在线列表不删除当前已保存或手动输入的模型，即使服务商暂时不再返回它。

自定义服务商同样允许点击更新：只要其地址提供兼容的 `/models` 响应即可成功；否则给出“不支持模型列表接口”的可理解提示，继续允许手动输入。

## 数据与组件边界

- `provider_catalog`：定义内置服务商、默认地址和推荐模型；无网络职责。
- `AIService`：新增读取模型列表的方法，负责网络请求、鉴权、超时、响应解析和错误归类。
- `model_catalog_cache`：负责按服务商与地址读写模型列表及更新时间，不接触 API Key。
- `AIModelDialog`：负责联动展示、手动输入、触发异步更新和状态反馈。
- 现有 `AIModelConfig`、数据库模型配置表和凭据加密流程保持兼容；无需为已保存配置做数据库迁移。

缓存使用配置目录下的独立 JSON 文件，采用版本化结构和原子替换写入。缓存损坏时忽略该文件并回退到内置目录，不阻止应用启动。

## 状态与错误处理

模型同步至少区分：

- 未填写必需的 API Key。
- 鉴权失败。
- 地址或网络不可达。
- 请求超时。
- 服务商未实现 `/models`。
- 返回内容不是兼容格式。
- 成功但模型列表为空。

错误只在当前对话框中呈现，不弹出连续阻塞式消息框。再次编辑地址、密钥或服务商后允许立即重试。关闭对话框时应安全取消或忽略未完成请求的回调，避免操作已销毁控件。

## Apple 风格交互要求

这是设置类生产力界面，动效保持克制：

- 按钮按下和状态切换提供即时、短促反馈。
- 更新成功后仅对模型框做一次轻柔强调，不使用大面积位移或持续动画。
- 加载超过短暂阈值才显示进度提示，避免快速请求造成闪烁。
- 所有主要控件保持清晰焦点态、键盘可操作和足够点击区域。
- 动画可被“减少动态效果”设置关闭，关闭后用颜色/文字状态替代。
- 不以低对比度灰色表达关键说明或错误，商务风、科技风等主题均满足可读性要求。

## 兼容性与安全

- API Key 只进入现有凭据加密服务和请求头，不写入模型缓存、日志或错误文本。
- 已保存的旧配置仍按原有字段载入；未知服务商显示为“自定义”，原地址和模型名不丢失。
- 在线响应仅作为字符串数据处理，模型名称不得改变请求地址或执行本地代码。
- 网络请求设置有限超时和合理的响应大小上限。

## 验证策略

单元测试覆盖：

- 服务商到默认地址和内置模型的映射。
- Base URL 规范化。
- `/models` 成功、空列表、重复项、异常结构和常见 HTTP 错误。
- 缓存写入、读取、隔离、损坏回退及不包含密钥。
- 旧配置映射到内置服务商或自定义服务商。

界面测试覆盖：

- 切换服务商自动填充地址。
- 模型下拉框可选择也可输入。
- 更新按钮的加载、成功、失败和重试状态。
- 手动模型不会因同步失败或切换下拉项而丢失。
- 各主题下文字可读，减少动态效果时无依赖动画的信息表达。

最后运行现有服务层、窗口及 Apple Design 回归测试，确认聊天、报告和工具页仍能使用原有模型配置。
